# UI ユーザビリティレビュー（v2.2 Phase 5）

実施日: 2026-11-01　方法: モック transport（ブラウザ開発モード）で 4 画面を順に操作し、`apps/desktop/e2e/ux-walkthrough.spec.ts`（`UX_WALKTHROUGH=1` で実行）が `.tmp/ux/*.png` に保存したスクリーンショット 11 枚と、実 CLI ドッグフーディング（`test-results/dogfood/*.json`、`docs/dogfood-review.json`）の結果画面を、**CLI を使わない利用者**の視点で評価した。外部テスターは確保できなかったため、評価者は実装者 1 名（後述の「外部テスター募集時の観点」を残す）。

評価観点（指示どおり）: 初回セットアップ / プロジェクト選択 / 質問の分かりやすさ / 承認画面 / 進捗表示 / NEEDS_HUMAN 時の案内 / 結果・差分・レビュー。

## 良い点（維持する）

- **セットアップチェック**（01）: 失敗項目が「失敗」バッジ＋原因＋「修正方法」の 3 段で表示され、色だけに頼らない。環境 NG でも履歴閲覧は可能で、「開始」ボタンの横に開始できない理由が文章で出る。
- **プロジェクト選択**（02）: Git リポジトリでないフォルダーは「原因」「修正案」「エラーコード」を分けて表示。検出した事実（ブランチ・パッケージ管理・テスト方式）は表で確認できる。
- **質問**（04/05）: 1 ラウンド最大 3 問、必須 / 任意のバッジ、選択肢＋自由入力、AI の推奨案は「確定事項ではない」と明示。スキップと「戻る」がある。
- **承認画面**（06/07）: データ送信の同意が明示され、同意しないと承認できない。「開始できない理由」が列挙される。要件・対象外・受入条件を直接編集でき、修正は新しいリビジョンになって承認がリセットされる。意思決定ログに質問 / 矛盾 / 修正の出所と履歴が残る（v2.2）。
- **進捗**（08）: 起動前検査 → 実装 → 検証 → レビュー → 完了 のステップ表示、ラウンド数、経過時間、キャンセルの影響説明。
- **結果**（09/10）: 状態・理由コードの日本語ラベル、「次の手動操作」の番号付きリスト、変更ファイル、未解決の指摘、Policy Gate、egress（許可 / 拒否 / エラー）の区別、差分とレポートを折りたたみで同居。push / merge / deploy をしない旨を常時表示。

## NEEDS_HUMAN 時の案内（実 CLI の実例で確認）

ドッグフーディング `self-masking-patterns`（3 ラウンド changes_requested → `MAX_ROUNDS`）と `v22-policy-loop`（v2.2 Phase 2 の実測、`docs/FINAL_REPORT.md` 参照）の結果画面では、状態「要確認（NEEDS_HUMAN）」、理由コードの日本語ラベル、詳細（どのラウンドで何が原因か）、「次の手動操作」、未解決の指摘（severity / ファイル:行 / 推奨）、Policy Gate の検出（ルール ID / ファイル:行 / 証拠）が表示される。情報自体は揃っているが、上表 P0 のとおり「利用者が次に押すもの」が無い。
