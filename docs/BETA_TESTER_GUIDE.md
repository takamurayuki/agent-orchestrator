# Agent Orchestrator β版 テスター向けガイド（v0.1.0、未署名）

このアプリは、日本語で「こういう機能を追加したい」と書くと、質問に答えて内容を確認した後、AI（Claude Code）が隔離された環境でコードを書き、検証（型チェック・lint・テスト）と別の AI（Codex）によるレビューを通して結果を見せてくれるツールです。**あなたのプロジェクトそのものは変更しません。** 変更は「作業用コピー」に保存され、取り込むかどうかはあなたが決めます。

> **β版の注意**
> - **未署名のアプリです。** インストール時に Windows の SmartScreen 警告（「WindowsによってPCが保護されました」）が出ます。配布元を確認した上で「詳細情報」→「実行」で進めてください。一般公開版ではありません。配布されたファイル以外から入手しないでください。
> - **AI の利用料金が発生します**（下記「料金が発生する操作」）。
> - **プロジェクトの内容（コード・設定）が AI 提供者（Anthropic / OpenAI）に送信されます。** 機密のプロジェクトでは使わないでください。

## 1. 事前準備（ご自身で用意するもの）

| 必要なもの | 確認方法 | 無いとどうなるか |
|---|---|---|
| Windows 11（64 bit） | 設定 → システム → バージョン情報 | 他の OS 向けの配布物はありません |
| **Docker Desktop**（起動していること） | タスクバーのクジラのアイコン。初回は WSL2 の有効化を求められます | アプリの「セットアップチェック」に「失敗」と表示され、開始できません |
| **Git** | スタートメニューで「Git」を検索 | 同上 |
| **Claude Code のログイン**（Anthropic のアカウント） | ターミナルで `claude` を一度起動してログイン | 「Claude 認証」が失敗と表示されます |
| **Codex のログイン**（OpenAI のアカウント） | ターミナルで `codex login` | 「Codex 認証」が失敗と表示されます |
| 試したい **Git 管理されたプロジェクト**（Node.js 製、`package.json` に `typecheck` / `lint` / `test:run` スクリプトがあるもの） | — | プロジェクト選択時に「検証スクリプトが不足」と表示され、開始できません |
| ネットワーク（Docker Hub、npm レジストリ、Anthropic / OpenAI への接続） | — | 初回セットアップや実行が失敗します（プロキシ環境では Docker Desktop のプロキシ設定が必要） |

Node.js や pnpm は**不要**です（アプリに同梱されています）。ログインは一度だけ必要で、アプリはパスワードや API キーを保存・表示しません。

## 2. インストールと初回セットアップ（約 5〜10 分）

1. `Agent Orchestrator_0.1.0_x64-setup.exe` を実行します（SmartScreen は「詳細情報」→「実行」）。
2. アプリを起動すると「セットアップチェック」が自動で走ります。赤い「失敗」の項目があれば「修正方法」に従って直し、「再チェック」を押してください。
3. 「サンドボックスを準備する」が表示されたら、**同意にチェック**して「サンドボックスを準備する」を押します。Docker Hub から基盤イメージを取得し（約 70 MB）、AI を動かすためのイメージを作ります。初回は数分かかります（ネットワーク速度と PC 性能に依存。参考: キャッシュ無しで 約 5 分、キャッシュありで約 40 秒）。
4. 「実行可能」になれば準備完了です。

## 3. 使い方（1 回の依頼）

1. **プロジェクトフォルダー**: 「フォルダーを選択…」で Git 管理されたプロジェクトのルートを選び、「選択」。
2. **依頼内容**: やりたいことを日本語で書いて「開始」。例: 「ログイン失敗を 5 回で一時ロックする機能を追加したい」「`src/lib/time.ts` に残り時間を mm:ss に整形する関数を追加してテストも書いて」
   - 1 回の依頼は「1 機能、数ファイル程度」が目安です。大きすぎると修正回数の上限（3 回）に達しやすくなります。
3. **質問に回答**: AI が不明点を最大 3 問ずつ聞きます。推奨案は参考で、決めるのはあなたです。「戻る」で前の回答を直せます。
4. **要件サマリーを確認して承認**: 「何を作るか」「受入条件」「制約」を読み、問題なければ同意にチェックして「この内容で開発を開始」。修正したい場合は「要件を修正する」を開いて編集すると、承認は取り直しになります。
5. **実行を待つ**: 「現在の処理」に進み具合が出ます（通常 2〜10 分）。「実行を停止する」でいつでも止められます。
6. **結果を見る**: 見出しが結果を示します。
   - 「開発が完了しました（元のプロジェクトへの取り込みはまだです）」→ 「変更内容を見る」「作業用コピーのフォルダーを開く」で確認し、よければお使いの Git ツールで取り込んでください。
   - 「人の判断が必要です」→ AI だけでは解決できなかった理由と次にできることが表示されます。変更は未完成なので取り込まないでください。
   - 「実行前の確認で止まりました」→ 環境やプロジェクトの問題です。AI は動いておらず料金もかかっていません。

## 4. 料金が発生する操作

| 操作 | 発生する料金 |
|---|---|
| 「開始」（ヒアリング） | Claude（質問の生成・要件整理・矛盾検出）: 1 回の依頼で数円〜数十円 |
| 「この内容で開発を開始」（実行） | Claude Code（実装、最大 3 回）: 小さな依頼で 10〜30 円程度（実測: 1 ラウンド約 $0.05〜0.12）。Codex（レビュー）: OpenAI のプランに応じて消費 |
| セットアップチェック、プロジェクト選択、結果の閲覧、停止 | 無料 |

上限: 実装 1 回あたり $10、修正は最大 3 回、実行全体は 45 分で自動停止します。

## 5. 既知の制限

- 未署名（SmartScreen 警告）。別 PC / VM での動作検証は未実施です（開発機で検証）。
- 対応するプロジェクトは Node.js + pnpm（`typecheck` / `lint` / `test:run` スクリプトが必要）のみ。
- 元のプロジェクトへの反映（コミット・push）は行いません。作業用コピーからの取り込みは手動です。
- AI の変更がプロジェクトの lint ルールやテストを弱めた場合（例: `eslint-disable` の追加）は自動的に差し戻され、解消しなければ「人の判断が必要です」で止まります。
- 1 度に実行できる依頼は 1 つです。
- 「完了」は検証とレビューを通過したという意味で、バグがないことを保証しません。必ず内容を確認してください。

## 6. 困ったとき（トラブルシューティング）

| 症状 | 原因と対処 |
|---|---|
| SmartScreen で実行できない | 「詳細情報」→「実行」。β版は未署名です |
| 「Docker CLI: 失敗」「Docker デーモン: 失敗」 | Docker Desktop を起動し、Settings → General で WSL 2 based engine を有効にして「再チェック」 |
| 「Git: 失敗」 | Git for Windows をインストールし、PC を再起動（PATH 反映）後に「再チェック」 |
| 「Claude 認証 / Codex 認証: 失敗」 | ターミナルで `claude`（または `codex login`）を実行してログイン後、「再チェック」 |
| サンドボックスの準備が「失敗」 | 表示される「原因」と「復旧方法」に従い「再試行」。ネットワーク（Docker Hub / npm）に到達できない場合はプロキシの設定を確認。「ダイジェスト不一致」は停止が正常です（開発者に連絡） |
| プロジェクトを選ぶと「Git リポジトリではありません」 | Git 管理されたフォルダーのルートを選んでください |
| 「検証スクリプトが不足しています」 | プロジェクトの `package.json` に `typecheck` / `lint` / `test:run` を用意してください |
| 「実行前の確認で止まりました」 | 変更前のプロジェクトで `typecheck` / `lint` / `test:run` が通る状態にしてから再実行 |
| 「人の判断が必要です」 | 「未解決の指摘」を読み、依頼を小さく分ける／具体的にする／指摘内容を開発者に相談 |
| 実行が長い | 「実行を停止する」で止められます。途中の変更は作業用コピーに残り、元のプロジェクトは変わりません |
| アプリが起動しない | `%LOCALAPPDATA%\agent-orchestrator\app-data` を退避してから再起動。改善しなければ問題報告へ |

## 7. 問題の報告

`docs/ISSUE_TEMPLATE.md` の形式でお送りください。アプリの「内部ステータス・技術情報」に表示される Run ID と、`%LOCALAPPDATA%\agent-orchestrator\app-data\runs\<Run ID>\report.md` を添えていただけると助かります（ログは秘密情報をマスキング済みですが、送付前にご確認ください）。

## 8. アンインストール

「設定 → アプリ → Agent Orchestrator → アンインストール」。履歴や作業用コピー（`%LOCALAPPDATA%\agent-orchestrator\app-data`）と Docker イメージ（`agent-orchestrator-sandbox:0.1.0`、`agent-orchestrator-egress-proxy:0.1.0`）は残るため、不要なら手動で削除してください。
