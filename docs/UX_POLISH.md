# UI / UX 磨き込み（v0.3 作業開始、2026-11-02）

外部テスターに v0.2.2（タグ `v0.2.2`）を確認してもらっている間に、画面の情報設計と視覚表現を見直した。バックエンドの状態遷移・IPC・Policy Gate・完了ゲートは変更していない（表示だけ）。自動テストで使う `data-testid` と主要な文言は維持し、Playwright 31 件は全件 PASS。

## 1. 課題（磨き込み前）

- すべての情報が同じ重みで並び、ぱっと見て「今なにをすればよいか」が分からない（ホームは環境チェック 9 項目とプロジェクト詳細 12 行が常時表示、承認画面は 8 節の長文、結果画面は説明文の壁）。
- 色が多く（枠線付きバッジ、青い点線枠の推奨案、濃い枠の警告）、注意を引く要素が競合する。
- 主操作（開始・回答・承認・変更内容を見る）が画面下に埋もれ、視線の終点が定まらない。

## 2. 方針

| 原則 | 具体策 |
|---|---|
| 画面ごとに見出し 1 つ・主操作 1 つ | 各画面の先頭に `hero` カード（eyebrow + 見出し + 状態バッジ）。主操作は primary ボタン 1 つだけを右下または常時表示のアクションバーに置く |
| 構造で見せる | ホームは番号付きステップ（1 プロジェクト → 2 依頼 → 開始）。承認画面は要約タイル（機能要件 / 受入条件 / 変更範囲 / 対象外 / 生成物 / 確認方法）＋ 折りたたみの節（機能要件と受入条件だけ既定で展開）。結果画面は「何が起きたか / 変更の状態 / 次にできること」を 3 列の案内に |
| 補助情報は右のレールと折りたたみへ | 環境チェック・履歴・リポジトリ調査結果・回答履歴は背景色だけの quiet カード。正常な項目は「正常 N 件」に畳み、問題のある項目だけ常時表示 |
| 視線誘導 | 左上の見出し → 本文 → 右下の主操作。実行中はステップ（1〜6）を線でつないだ stepper とパルスする現在地。ラウンド・経過時間はタイルで数値を大きく |
| 色調 | 中立グレーの背景 + アクセント 1 色（青）。意味色（緑 / 琥珀 / 赤）は状態バッジと左のアクセント線だけに使い、枠線は薄く、バッジは塗りのみ。ダークモード対応は維持 |
| 動きは最小限 | 進行中を示す点のパルスと開閉の矢印だけ。`prefers-reduced-motion` で無効化 |

## 3. 変更した画面と部品

| 画面 / 部品 | 変更 |
|---|---|
| シェル（`App.svelte`、`app.css`） | ナビをピル型タブに、トークン（色・影・角丸・レール幅）を再定義。`hero` / `tiles` / `chips` / `stepnum` / `actionbar` / `section`（折りたたみ）/ `check-row` / `progress-bar` などの共通スタイルを追加 |
| ホーム（`Home.svelte`、`SetupCheck.svelte`、`HistoryList.svelte`） | 導入文 → ステップ 1（プロジェクト。概要は chips、事前診断は問題のある項目だけ常時表示、詳細は折りたたみ）→ ステップ 2（依頼。主操作「開始」を右下に）。右レールは環境チェック（状態 1 行 + 正常 N 件の折りたたみ）と最近の履歴（コンパクト） |
| ヒアリング（`Interview.svelte`、`QuestionCard.svelte`、`FactsPanel.svelte`） | 依頼文を見出しに、進捗は細いバー + 1 行。質問カードは番号 + 選択肢を大きな行に、推奨案は 1 行の注記、スキップはリンク。回答ボタンは常時表示のアクションバー。調査結果は確認済みを畳み、推測・未確定だけ展開 |
| 承認（`ApprovalOverview.svelte`） | 要約タイル + 折りたたみの節。承認（同意 + 開始）は常時表示のアクションバー |
| 実行中（`Running.svelte`） | hero に現在の処理（1 行）+ stepper + タイル。検証 / レビューは quiet カード |
| 結果（`Result.svelte`） | hero に見出し・要約・3 列の案内・主操作。停止理由の診断は独立カード（琥珀のアクセント線）。ポリシー違反は検出なしなら折りたたみ |
