# 限定β 外部ユーザーテスト手順書（協力者 2〜3 名向け）

> 状態: **未実施**（2026-11-01 時点）。実装者以外の協力者を確保できていないため、本書は実施手順と記録様式のみを定める。実施結果は本書末尾の記録票に追記する。

## 1. 目的

事前説明を最小限にした状態で、インストールから最初の開発依頼の結果確認までを協力者に操作してもらい、迷う箇所・不具合・理解度・継続利用意向を記録する。

## 2. 協力者への事前説明（これ以上は説明しない）

1. 「日本語で依頼を書くと、AI が隔離環境でコードを書き、検証とレビューを通して結果を見せるツールです。あなたのプロジェクトは変更しません。」
2. 渡すもの: インストーラ（未署名である旨の注意書き）、`docs/BETA_TESTER_GUIDE.md` へのリンク、問題報告テンプレート、試用用の小さな Git プロジェクト（または協力者自身のプロジェクトのコピー）。
3. 前提: Docker Desktop、Git、Claude Code と Codex のログインは協力者側で用意する（ガイド §1）。用意できない場合は「どこで詰まったか」を記録して終了してよい。

## 3. 課題（協力者に提示する依頼文の例）

| # | 依頼文 | 期待する結果 |

| T1 | 「`src/greet.ts` の `greet` に、名前が空文字のときは "Hello, stranger!" を返す仕様を追加してテストも書いて」 | 1〜2 ラウンドで完了 |

## 4. 記録項目（協力者 1 名につき 1 枚）

| 項目 | 記録方法 |
|---|---|
| インストールから初回実行までの時間 | インストーラ起動時刻 〜 最初の「開始」クリック時刻（セットアップ含む） |
| 操作に迷った回数 | 観察者が「10 秒以上止まった」「違うボタンを押した」「ガイドを見た」回数を数える |
| 人間の介入回数 | 観察者が助言した回数、および協力者が「要確認」で判断した回数 |
| 実行結果の理解度 | 結果画面を見て「何が起きたか」「次に何をすべきか」を協力者に説明してもらい、正しければ ○ |
| 発見した不具合 | 問題報告テンプレートで記録 |
| 継続利用したいか | 「使いたい / 条件付きで使いたい / 使わない」と理由 |

## 5. 観察者の注意

- 操作を代行しない。質問には「ガイドのどこを見ればよいか」だけ答える。
- 料金は観察者側が負担する前提で、1 名あたりの上限（例: $2）を決めておく。
- ログ・スクリーンショットを共有してもらう前に、秘密情報が含まれないことを協力者に確認してもらう。
